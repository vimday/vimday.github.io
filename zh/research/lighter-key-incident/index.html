Lighter 复盘｜交易密钥如何通向提款

三笔数字，三个口径

2026 年 11 月 16 日 10:11 UTC，一笔成功的以太坊交易记录了 Lighter 结算合约向外部地址转出 10,393,056.789298 USDC。我们用公共以太坊节点读取交易回执，核对了 USDC 合约的 Transfer 日志及 6 位小数。这笔转账确立了可以独立核实的流出金额。以太坊交易记录

签名通过了，密钥却失守了

Lighter 将入口归因于交易者使用的非官方签名实现。它在不同交易上重复使用了同一把 API 私钥的签名随机量，公开签名因而泄露了足以反推出私钥的信息。Lighter 表示官方 SDK、智能合约及平台基础设施未受这次失陷影响。原始签名样本和签名器代码未在复盘中披露，具体是哪段代码重复生成随机量仍无从核对。Lighter 技术说明

这里需要区分两种 nonce。签名 nonce 是签名算法内部的一次性秘密量。对于 Schnorr 类签名，两条签名若共用了这个秘密量，观察者可以消去共同项，剩下关于私钥的关系。交易 nonce 是请求中的防重放序号，服务端用它拒绝重复提交。一次新的交易可以拥有正确的序号，同时由已经恢复出的私钥签署。

签名验证回答的是「哪把密钥签了这条指令」，证明电路检查的是「状态变更是否符合编码规则」。两项验证都可以正常工作，而密钥仍然已不再代表交易者本人。

公共池改变了资产的受益人

Lighter 的常规提款只能发往账户自身绑定的钱包。事发时，账户创建的公共池被归入同一账户的子账户，但池的份额可以由外部账户持有。资金一旦进池，池份额就决定谁有权赎回资产。于是每一步单看都符合各自的授权规则，串起来却跨过了资产归属的边界。官方复盘中的资金路径

用一个简化的会计例子看风险。池里有 100 单位资产和 100 份份额，每份净值为 1。若另划入 900 单位资产且份额数保持 100，每份净值便升至 10。控制者即便只动用了「同一账户内划转」权限，外部份额持有人也能取得新增资产对应的赎回价值。这组数字只演示份额机制。

修复覆盖了哪几道边界

Lighter 先披露暂停提款及新建资金池，随后公布合约进入 Guardian 模式。官方复盘称安全委员会向受影响交易者返还约 500 万 USDC。18:21 UTC 的公告确认 Guardian 模式解除，充提恢复。恢复公告

已披露上线的改动有两项。向公共池划转增加钱包签名校验，隔断了此次的资金路径。交易查询不再返回原始 API 签名，减少新签名的暴露面。此前已经公开过的签名仍需要按已暴露来处理。Lighter 同时将 IP 白名单、单密钥权限和额度、签名随机量复用监测列为后续措施。修复及后续计划 · API 变更公告

对交易系统，验收应覆盖两个不同问题。签名侧检查并发和重启后是否仍使用受审阅的签名器，并在轮换后确认旧键被服务端拒绝。资金侧以交易密钥作为起点，逐项检查子账户、池、份额和出金地址。验收的最终对象是资产能否到达另一个受益人。

证据范围

本文复核了以太坊交易回执、运营方公告与公开文档。资金池内的状态变更依据平台披露，尚未通过完整的二层账本独立重放。若平台随后发布逐账户对账、补丁版本和返还凭证，可据此更新受损与返还数字。
