How a Lighter trading key opened a path to withdrawal

An Ethereum transfer confirms 10.39 million USDC left Lighter. The incident shows how a signing failure and a shared pool combined to move funds across accounts.

What the three figures measure

At 10:11 UTC on November 16, 2026, a successful Ethereum transaction moved 10,393,056.789298 USDC from Lighter’s settlement contract to an external address. We checked the receipt against a public Ethereum node and decoded the USDC contract’s Transfer log using six decimal places. That transaction establishes the independently verifiable outflow. Why valid signatures could expose the key

Lighter traced the initial compromise to a trader’s custom signing code. It reused the secret signing nonce with the same API key on different transactions. The signatures were public, which gave an observer enough information to recover the signing key. Lighter said the official SDKs, contracts and infrastructure were unaffected by the compromise. Its postmortem does not publish the affected signing code or sample signatures, leaving the precise implementation defect unverified. Lighter’s technical account

Two different values are often called a nonce. The signing nonce is a secret, single-use input to the signature algorithm. In a Schnorr-style scheme, reusing it across two different messages lets an observer eliminate that shared term and solve for the secret key. A transaction nonce is a request identifier used to reject replays. A new transaction can carry an unused identifier and still be signed by someone who reconstructed the key.

A valid signature identifies the credential that authorized an action. A validity proof checks that the action follows the encoded state transition rules. Both checks can pass after the credential stops representing the trader’s intent.

How the pool changed who could redeem

Lighter’s ordinary withdrawal path pays an account’s own wallet. At the time of the incident, an account-created public pool qualified as its subaccount for transfers, while separate accounts could hold pool shares. The pool’s trading account and the owners of its redemption rights were different things. An internal transfer could therefore move economic value across owners. Lighter’s account of the pool path

Consider a pool with 100 units of assets and 100 shares. Each share is worth one unit. Moving 900 more units into the same pool without issuing shares raises each share’s value to ten units. A transfer categorized as internal can thus increase a third party’s claim. This example illustrates the accounting, using hypothetical amounts.

The scope of the fixes

Lighter first disclosed a pause in withdrawals and pool creation. It subsequently reported enabling Guardian mode and returning about 5 million USDC to the affected trader through its Security Council. The 18:21 UTC announcement confirmed that Guardian mode was lifted and deposits and withdrawals had resumed. Restoration announcement

Two changes were reported as shipped. Transfers into a public pool gained a wallet signature requirement, closing the reported route into the pool. Transaction interfaces stopped returning raw API signatures, reducing exposure for new signatures. Previously disclosed signatures remain material to any investigation of key exposure. Lighter listed IP allowlists, per-key scopes and limits, and monitoring for nonce reuse as follow-up work. Incident findings · API changes

The incident suggests two distinct acceptance tests for a trading system. First, confirm the signer remains safe across concurrent requests and restarts, and verify that revoked credentials are rejected by the venue. Then start with a trading credential and follow every path through subaccounts, pools, shares and withdrawal destinations. The outcome to test is whether value can reach a different beneficiary.

Evidence and limits

This review checks the Ethereum receipt, operator announcements and published documentation. The in-pool state changes are attributed to Lighter’s account and have not been independently replayed from a complete rollup ledger. An account-by-account reconciliation, patch version and return receipts would let us revisit the impact figures.
